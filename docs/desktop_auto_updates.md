# Desktop app updates

Ninjy app updates replace the Electron app. They do not update, stop, reinstall or
re-enroll installed Bridge services, profiles or running agents. Bridge updates
remain a separate operation in Settings → Bridges.

Settings → App updates shows the installed `app.getVersion()`, Stable channel,
check time, download progress, retry and restart controls. The native App updates
menu also works when the Hub serves an older UI. A legacy desktop preload shows
manual upgrade guidance in the current UI. An old/unavailable renderer cannot
acknowledge safe restart preparation; use Later and manually install/relaunch.

Eligible signed apps check after 30 seconds and every six hours. Downloads are
automatic; normal quit and Later do not initiate installation or macOS native
staging. Restart to update first freezes editing, checks pending operations,
flushes composer drafts and workspace layout with checked storage writes, and
then asks for native confirmation with Later as the default. Finish sends/uploads,
remove/send pending attachments or quoted/task-card drafts, and save or discard
and close other forms/editors before restarting. Unsupported unsaved surfaces
block restart rather than claiming to preserve data they cannot flush. Editing
and new Bridge operations stay excluded until exit or explicit transaction abort.
An exit watchdog releases preparation if a native restart never completes. After
quit has been invoked, an error alone keeps the freeze held until actual exit,
a known page unload veto or that watchdog, so editing does not reopen while a
quit may still be pending.

Only macOS signed app bundles and signed Windows x64 NSIS installs are eligible.
Mounted DMGs, protected/read-only installs, missing/malformed policy or feed,
development builds, unpacked/portable Windows delivery, Store builds, Linux
(including AppImage) and Nix use manual/package-manager updates. No updater writes
to the Nix store. Windows additionally requires its NSIS uninstaller beside the
app, an NSIS registry InstallLocation matching the running app, matching nonempty
publisher configuration and signature verification. Copied/unregistered app
folders are manual-only.

## Release prerequisites

Public GitHub Releases at `tanmayv/heimdall-agent-manager` remain the host. No new
service, production change or embedded GitHub token is required. `app-update.yml`
is generated by electron-builder. The build-owned
`resources/desktop-update-policy.json` is written by
`scripts/release/desktop-update-policy.cjs` before code signing; it is never a UI
setting. Unsigned/manual builds have `updatesEnabled: false`. A numeric candidate
tag uses GitHub's prerelease flag and becomes visible only after promotion;
promotion keeps the app version and bytes unchanged. Alpha/beta suffix channels
are not supported, and downgrades are disabled even from a manually installed
newer candidate.

macOS signing/notarization requires these existing secret names:

- `MACOS_DEVELOPER_ID_P12_BASE64`, `MACOS_DEVELOPER_ID_P12_PASSWORD`
- `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`
- Optional PKG signing: `MACOS_DEVELOPER_ID_INSTALLER_P12_BASE64`,
  `MACOS_DEVELOPER_ID_INSTALLER_P12_PASSWORD`

The workflow maps the imported app identity to `CSC_NAME` and
`HEIMDALL_MACOS_CODESIGN_IDENTITY`; a signed desktop build sets
`HEIMDALL_DESKTOP_SIGNED_RELEASE=1` and forces code signing. Keep the existing
Developer ID/team, app ID `works.earendil.heimdall`, hardened runtime,
entitlements, notarization and stapling. ZIPs are update payloads; DMG/PKG are
manual installation media. Intel macOS remains opt-in and must include a matching
x64 ZIP and blockmap. ARM64 is the default published architecture.

Windows remains **manual-only until an operator configures signing**:

- Repository variable `WINDOWS_UPDATE_PUBLISHER_NAME`: the exact trusted
  Authenticode publisher name (prefer the certificate's full Subject/DN), with
  no guessed/default identity.
- Secrets `WIN_CSC_LINK`, `WIN_CSC_KEY_PASSWORD`: supported certificate signing
  inputs mapped to builder's `CSC_LINK`, `CSC_KEY_PASSWORD`.

Setting the publisher variable opts CI into a signed release. Missing signing
inputs then fail closed. CI forces signing and publisher configuration and checks
the final EXE with `Get-AuthenticodeSignature`. The runtime also compares the
policy publisher list with generated feed configuration. No custom signature
verifier or unsigned fallback is used. Hardware/cloud signing needs a separately
reviewed provider integration. Users of old unsigned Windows apps manually install
the first official signed release; old binaries cannot be secured retroactively.
The presence, validity, expiry and permissions of these external credentials have
not been verified on this Linux implementation host.

Release and promotion jobs run `validate-desktop-updates.py` against the final
NSIS/ZIP bytes: matching version, architecture, file names, size, SHA-512, legacy
metadata fields and required blockmaps. Promotion downloads and verifies the
payloads before changing the candidate flag. SHA-512 protects integrity relative
to the feed; publisher authentication comes from native signatures, not that
unsigned digest. Linux release artifacts remain manual/package-manager media.

## Native acceptance still required

Linux fixtures and builds do **not** establish native rollout readiness. Before
publishing/enabling delivery, run signed N→N+1 acceptance on macOS ARM64, opted-in
Intel and Windows x64 with the actual configured publisher. Verify download,
Later/ordinary quit, explicit restart/relaunch, installed version, latest composer
draft/layout restoration, refusal during pending edits or Bridge operations,
continued Bridge/agent operation, offline retry and tampered/wrong-publisher
rejection. Verify protected install guidance and manual bootstrap from old apps.
macOS PKG receipts and receipt-managed Bridge components must remain untouched.

The pinned `electron-updater` 6.8.12 macOS `quitAndInstall()` leaves a persistent
native completion→quit callback armed after errors; this implementation never
calls that method on macOS. Its narrow adapter uses public Electron native staging
only after consent and held preparation, validates the epoch immediately before
native quit, disarms its listeners before releasing guards, and permits one
staging attempt per process. After failed/aborted staging, relaunch or manually
update; a late completion cannot make the application trigger quit.

Native staging cannot be reliably cancelled through the documented API. Abort
does not claim to discard an already staged payload or prevent Squirrel applying
it on a later ordinary user exit. Native acceptance must delay staging while
attempting edits/navigation and inject an error followed by late completion.
If native behavior conflicts with the required rollout policy, keep rollout
disabled and resolve it before publishing. No release is published by the
implementation task or its local checks.
